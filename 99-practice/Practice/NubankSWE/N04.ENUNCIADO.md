Para este simulado, vamos focar em um problema que mistura **agregação de dados**, **janelas de tempo (TTL)** e **lógica de fraude**, que é o "padrão ouro" das questões mais difíceis do CodeSignal para empresas como o Nubank.

### O Problema: "Transaction Velocity Monitor"

**Cenário:**
O Nubank quer monitorar transações suspeitas. Uma transação é marcada como `FRAUD` se o usuário tentar gastar mais do que um valor $X$ em um intervalo de **60 segundos**.

**Regras:**
1.  **TRANSFER `<timestamp> <userId> <amount>`**: Se a soma das transferências bem-sucedidas desse usuário nos últimos 60 segundos (incluindo a atual) exceder o limite de **1000**, a transação deve ser `REJECTED`. Caso contrário, `ACCEPTED`.
2.  **Lógica de Tempo:** O timestamp é um inteiro em segundos.
3.  **Saída:** Retornar um array de strings com o status de cada transação.

---

### Código Completo (Solução + Runner)

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

namespace NubankVelocitySimulado
{
    // Representa uma transação bem-sucedida para controle de histórico
    public record PastTx(long Timestamp, decimal Amount);

    public class Solution
    {
        public string[] solution(string[][] queries)
        {
            // Dicionário para armazenar o histórico de transações aceitas por usuário
            var userHistory = new Dictionary<string, List<PastTx>>();
            List<string> results = new List<string>();

            foreach (var q in queries)
            {
                long time = long.Parse(q[0]);
                string userId = q[2];
                decimal amount = decimal.Parse(q[3]);

                if (!userHistory.ContainsKey(userId))
                {
                    userHistory[userId] = new List<PastTx>();
                }

                // 1. Limpeza: Remove transações mais velhas que 60 segundos da janela atual
                // Isso mantém a performance e a corretude do cálculo
                userHistory[userId].RemoveAll(tx => tx.Timestamp <= time - 60);

                // 2. Cálculo da "Velocidade": Soma do que foi gasto nos últimos 60s
                decimal windowSum = userHistory[userId].Sum(tx => tx.Amount);

                // 3. Regra de Negócio
                if (windowSum + amount > 1000)
                {
                    results.Add("REJECTED");
                }
                else
                {
                    // Se aceita, adiciona ao histórico para impactar as próximas
                    userHistory[userId].Add(new PastTx(time, amount));
                    results.Add("ACCEPTED");
                }
            }

            return results.ToArray();
        }
    }

    // --- CÓDIGO DO PROBLEMA (RUNNER) ---
    class Program
    {
        static void Main(string[] args)
        {
            var sol = new Solution();

            // [timestamp, command, userId, amount]
            string[][] input = new string[][]
            {
                new string[] { "10", "TRANSFER", "user1", "500" },  // ACCEPTED (soma 500)
                new string[] { "20", "TRANSFER", "user1", "400" },  // ACCEPTED (soma 900)
                new string[] { "30", "TRANSFER", "user1", "200" },  // REJECTED (900+200 > 1000)
                new string[] { "71", "TRANSFER", "user1", "600" },  // ACCEPTED (Tx de 10s expirou, soma era 400, 400+600 <= 1000)
                new string[] { "72", "TRANSFER", "user2", "1100" }  // REJECTED (Acima do limite individual)
            };

            Console.WriteLine("=== Simulador de Monitoramento de Velocidade (Anti-Fraude) ===");
            var results = sol.solution(input);

            for (int i = 0; i < results.Length; i++)
            {
                Console.WriteLine($"Transação {i + 1}: {results[i]}");
            }

            /*
               Explicação do Caso de Teste:
               - T:10 -> user1 gasta 500. Total 60s: 500. (OK)
               - T:20 -> user1 gasta 400. Total 60s: 900. (OK)
               - T:30 -> user1 tenta 200. Total 60s seria 1100. (REJECTED)
               - T:71 -> A transação de T:10 saiu da janela (71-60 = 11). 
                         Sobrou apenas a de T:20 (400). 
                         400 + 600 = 1000. (OK)
            */

            Console.WriteLine("\nPressione Enter para fechar.");
            Console.ReadLine();
        }
    }
}
```

### Por que este exercício é crucial para o CodeSignal?

1.  **Lógica de Janela Deslizante (Sliding Window):** Este é o conceito mais comum em questões de nível 3 e 4. Você precisa filtrar dados baseados em uma condição de tempo relativa ao `timestamp` atual.
2.  **Otimização de Performance:** 
    *   Sêniores notam que `RemoveAll` em uma lista pequena é aceitável. 
    *   *Dica Pro:* Se o volume de dados fosse enorme, você usaria uma `Queue<PastTx>` para remover apenas do início (onde estão as mais velhas), tornando a limpeza $O(1)$ em vez de $O(n)$. Mencionar ou implementar isso no comentário do código ganha muitos pontos.
3.  **Gestão de Estado por Usuário:** O uso de `Dictionary<string, List<...>>` mostra que você sabe isolar contextos de dados.
4.  **Parsing de Tipos:** Novamente, converter `string` para `long` e `decimal` corretamente é o básico esperado de um desenvolvedor backend.

### Dicas Finais para o dia da Prova:
*   **Fique atento aos limites:** Se o problema diz "nos últimos 60 segundos", verifique se é inclusivo (`<= time - 60`) ou exclusivo (`< time - 60`). No CodeSignal, um segundo de diferença faz você falhar em metade dos testes.
*   **Nomes de Variáveis:** No CodeSignal, use nomes claros como `windowSum` ou `currentTime`. O código é lido por revisores humanos no Nubank após você passar pelo bot.
*   **Atenção ao Retorno:** Se o exercício pede um array de strings, garanta que seu `List<string>` seja convertido com `.ToArray()` no final.</PastTx>
