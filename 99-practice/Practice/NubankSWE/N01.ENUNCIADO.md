## Simulado Estilo CodeSignal (Nível Sênior)

### O Problema: "The Transaction Sequence Validator"

**Contexto:**
Você recebe uma lista de operações bancárias. Cada operação é uma string no formato `"DEPOSIT <userId> <amount>"`, `"WITHDRAW <userId> <amount>"` ou `"TRANSFER <fromId> <toId> <amount>"`. 

Além disso, cada operação possui um **timestamp** único e crescente. O Nubank quer que você processe essas operações e retorne o estado final do saldo de cada conta que interagiu com o sistema, ordenado pelo ID da conta de forma crescente.

**Regras:**
1.  **Withdraw/Transfer:** Só podem ocorrer se o saldo for suficiente. Se não for, a operação é **ignorada** silenciosamente.
2.  **Limite de Cashback:** A cada 10 depósitos bem-sucedidos de um usuário, ele recebe 2% do valor total depositado nesses 10 depósitos como um bônus.
3.  **Saída:** Uma lista de strings no formato `"userId:balance"`.

### Exemplo:
**Input:**
```csharp
queries = [
    "DEPOSIT u1 100",
    "DEPOSIT u2 200",
    "TRANSFER u1 u2 50",
    "WITHDRAW u1 60"
]
```
**Output:**
```csharp
["u1:50", "u2:250"]
```
*(Note que o WITHDRAW de 60 foi ignorado pois u1 só tinha 50 após a transferência)*.

## Estratégia de Resolução no CodeSignal

No CodeSignal, você não tem tempo para criar arquiteturas complexas. O foco é **Parsing e Dicionários**.

### 1. Preparação (Parsing)
Use `string.Split(' ')` para identificar o comando e os parâmetros. Converta os valores numéricos imediatamente.

### 2. Estrutura de Dados
Use um `SortedDictionary<string, long>` (ou `decimal`) para manter os saldos. O `SortedDictionary` já garante que, ao iterar no final, os IDs estarão em ordem alfabética/crescente, economizando um passo de `OrderBy`.

### 3. Implementação (Código para Praticar)

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

public class Solution {
    public string[] solution(string[][] queries) {
        // Usamos SortedDictionary para manter a ordem dos IDs automaticamente
        var balances = new SortedDictionary<string, decimal>();
        // Controle de cashback (opcional conforme o enunciado)
        var depositCount = new Dictionary<string, int>();
        var totalDeposited = new Dictionary<string, decimal>();

        foreach (var q in queries) {
            string command = q[0];
            string userId = q[1];
            
            if (command == "DEPOSIT") {
                decimal amount = decimal.Parse(q[2]);
                AddBalance(balances, userId, amount);
                
                // Lógica de Cashback (comum em desafios Nubank/CodeSignal)
                UpdateCashback(userId, amount, balances, depositCount, totalDeposited);
            } 
            else if (command == "WITHDRAW") {
                decimal amount = decimal.Parse(q[2]);
                if (balances.ContainsKey(userId) && balances[userId] >= amount) {
                    balances[userId] -= amount;
                }
            } 
            else if (command == "TRANSFER") {
                string toId = q[2];
                decimal amount = decimal.Parse(q[3]);
                if (balances.ContainsKey(userId) && balances[userId] >= amount) {
                    balances[userId] -= amount;
                    AddBalance(balances, toId, amount);
                }
            }
        }

        return balances.Select(x => $"{x.Key}:{x.Value}").ToArray();
    }

    private void AddBalance(SortedDictionary<string, decimal> dict, string id, decimal val) {
        if (!dict.ContainsKey(id)) dict[id] = 0;
        dict[id] += val;
```

## Dicas de Ouro para o CodeSignal:

1.  **Não perca tempo com `TryGet` ou `Async`:** O CodeSignal é síncrono e os inputs costumam ser bem formatados. Se o enunciado garante que o valor é numérico, `int.Parse` é mais rápido de digitar que `TryParse`.
2.  **Cuidado com `double`:** Para valores financeiros, o CodeSignal pode ter testes com muitas casas decimais. Use `long` (multiplicando por 100 para centavos) ou `decimal`.
3.  **Complexidade de Tempo:** Se houver uma busca dentro de um loop, use `HashSet` ou `Dictionary`. Se o teste travar em "Time Limit Exceeded", você provavelmente usou um `.ToList().Find()` dentro de um loop de 100.000 iterações.
4.  **A Questão 4:** Geralmente é uma questão de matriz ou manipulação de strings pesada. Se travar nela, garanta que a 1, 2 e 3 estão perfeitas (100% de cobertura de testes). No CodeSignal, consistência vale mais do que tentar a difícil e entregar com bugs.
